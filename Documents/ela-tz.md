# ELA — English Learning App

Техническое задание. Клиентская часть.

# Введение

## Проблема

Людям, которые учат английский, сложно освоить язык системно. Типичные причины:

- **Знания разрознены.** Грамматика, лексика, аудирование и чтение изучаются в разных приложениях и книгах, поэтому нет цельной картины.
- **Слова быстро забываются.** Выученные слова не повторяются вовремя, и результат не закрепляется.
- **Нет наглядного результата.** Человек не видит, сколько он уже выучил, и теряет мотивацию.
- **Нет контроля качества материалов.** Ошибки в заданиях и переводах портят обучение.

## Цель

Создать приложение для macOS, Windows и iOS, в котором пользователь системно изучает английский язык: проходит уроки, учит слова, слушает, читает, повторяет слова интервальными повторениями и видит свой прогресс на пути к выбранному уровню от A1 до C2.

## Описание приложения

Приложение работает на трёх платформах с единым дизайном. Набор элементов и логика одинаковы, отличается только компоновка под размер экрана.

Пользователь учится без регистрации. Аккаунт нужен ему, чтобы сохранить прогресс на сервере и переносить его между устройствами. Для ролей Moderator, Administrator и Owner аккаунт обязателен.

Разделы Grammar, Vocabulary, Listening, Reading и Homework можно скачать на устройство и заниматься без сети. Словарь и Flashcards всегда работают без сети. Учебный материал создаёт и загружает Administrator, проверяет Moderator. Пользователь материал не загружает.

Первый запуск требует подключения к интернету: сервер регистрирует устройство, чтобы позже вести счётчик занятий для подписки.

## Границы первой версии

В первую версию входят: Grammar, Vocabulary, Listening, Reading, Homework, словарь и Flashcards, цели и achievements, streak, прогресс, роли, регистрация и вход, скачивание разделов, настройки.

Вне первой версии:

- подписка и лимиты занятий, лимит словаря и лимит общения с AI;
- чат с AI;
- публикации, тьюторы, клубы и сообщество;
- восстановление пароля и подтверждение email;
- загрузка материалов файлом;
- уровни по каждому разделу (в первой версии один общий уровень);
- кэш данных сервера;
- уведомления об авторах.

Архитектура клиента закладывается под эти функции.

# 1 Описание системы

## 1.1 Клиентская часть

Клиентская часть описана через прецеденты. Прецеденты сгруппированы по ролям: общие и пользовательские, затем Moderator, Administrator, Owner. После прецедентов описаны окна и навигация, данные клиента и нефункциональные требования.

### Общие правила

Правила действуют во всех учебных прецедентах (1.1.10–1.1.14) и не повторяются в каждом.

1. **Доступность раздела.** Единица раздела открывается, если раздел скачан или есть сеть. Если раздел не скачан и сети нет, система показывает сообщение, единица недоступна.
2. **Потеря сети во время занятия.** Раздел не скачан: система уведомляет, что сеть пропала, и блокирует дальнейшие шаги. Место сохраняется, занятие продолжается после возврата сети. Раздел скачан: потеря сети ничего не меняет.
3. **Прерывание.** Если занятие прервано, система сохраняет место, ответы и список пропущенных заданий. Продолжение через «Continue lesson» на Home.
4. **Skip.** Пропущенное задание возвращается в конце. Занятие не завершено, пока выполнены не все задания.
5. **Повтор.** Статус «пройдено» не снимается, результат заменяется последним.
6. **Лимит занятий.** Предусмотрена проверка лимита при выборе единицы. В первой версии она выключена.
7. **Завершение.** Занятие завершено, когда выполнены все задания (для Reading: нажата «Finish»). Система сохраняет результат, обновляет прогресс и streak и открывает «Результат занятия». Результат (доля верных ответов) на статус «пройдено» не влияет.
8. **Предусловие учебных прецедентов.** Устройство зарегистрировано (1.1.2), целевой уровень выбран (1.1.3).

### 1.1.1 Роли

В системе четыре роли:

- **User.** Учится. Аккаунт не обязателен.
- **Moderator.** Проверяет материалы. Наследует права User. Аккаунт обязателен.
- **Administrator.** Загружает материалы, управляет пользователями, смотрит статистику. Наследует права Moderator. Аккаунт обязателен.
- **Owner.** Выдаёт и отзывает токены-приглашения, назначает Administrator. Наследует права Administrator. Создаётся только командой на сервере, в приложении Owner создать нельзя.

Moderator создаётся токеном-приглашением от Owner или назначением Administrator. Administrator создаётся токеном от Owner или назначением Owner существующему аккаунту.

### 1.1.2 Зарегистрировать устройство

- **Роль:** User (запускается системой).
- **Цель:** сервер знает устройство и ведёт для него счётчик занятий.
- **Предусловия:** первый запуск, идентификатор устройства не создан.
- **Исходное окно:** запуск приложения.
- **Итоговое окно:** Выбор цели.
- **Основной сценарий:**
  1. Система создаёт идентификатор устройства и сохраняет его в защищённом хранилище ОС.
  2. Система отправляет идентификатор на сервер.
  3. Сервер создаёт запись, использовано занятий: 0.
  4. Система открывает окно «Выбор цели».
- **Альтернативы и ошибки:**
  - 2а. Нет сети или сервер недоступен: окно «Нужно подключение» с кнопкой «Повторить». Дальше пользователя не пускаем.
  - 2б. Идентификатор создан, но сервер не подтвердил: при повторе отправляется тот же идентификатор.
- **Постусловия:** пользователь видит «Выбор цели». На сервере есть запись об устройстве, идентификатор сохранён на устройстве.
- **Запросы к серверу:** зарегистрировать устройство.

### 1.1.3 Выбрать целевой уровень

- **Роль:** User.
- **Цель:** задать уровень A1–C2, к которому идёт пользователь, и интересы.
- **Предусловия:** устройство зарегистрировано (1.1.2), целевой уровень не задан.
- **Исходное окно:** Выбор цели.
- **Итоговое окно:** Home.
- **Основной сценарий («Знаю свою цель»):**
  1. Пользователь выбирает «Знаю свою цель».
  2. Система показывает окно «Выбор уровня» с уровнями A1–C2.
  3. Пользователь выбирает уровень.
  4. Система показывает окно «Выбор интересов».
  5. Пользователь выбирает интересы, минимум один.
  6. Система сохраняет целевой уровень и интересы на устройстве и открывает Home.
- **Альтернативы и ошибки:**
  - 1а. «Не знаю цель»: система показывает «Выбор интересов», пользователь выбирает минимум один интерес. Система проводит тест уровня, определяет текущий уровень и предлагает следующий. Пользователь подтверждает предложенный уровень или выбирает другой. Система сохраняет уровень и интересы и открывает Home.
  - 1б. Текущий уровень C2: система предлагает целевой уровень C2.
  - 1в. Тест прерван: прогресс теста сохранён на устройстве. При следующем запуске система предлагает «Продолжить» или «Начать заново».
  - 1г. Приложение удалено во время теста: прогресс теста потерян, тест начинается заново.
  - 5а. Не выбрано ни одного интереса: перейти дальше нельзя.
  - *. Интересы меняют порядок тем, выбранные идут первыми. Остальные темы остаются доступными.
- **Постусловия:** пользователь видит Home. Целевой уровень и интересы сохранены, темы упорядочены по интересам.
- **Запросы к серверу:** нет.

### 1.1.4 Зарегистрироваться

- **Роль:** User. Moderator и Administrator регистрируются по токену-приглашению.
- **Цель:** создать аккаунт и привязать к нему устройство.
- **Предусловия:** устройство зарегистрировано (1.1.2). Для Moderator и Administrator есть токен от Owner.
- **Исходное окно:** Профиль или Вход.
- **Итоговое окно:** Профиль.
- **Основной сценарий:**
  1. Пользователь открывает «Регистрация».
  2. Пользователь вводит email и пароль. При наличии токена выбирает «У меня есть токен» и вводит его.
  3. Система проверяет формат email и пароль (минимум 8 символов).
  4. Сервер создаёт аккаунт. Если токен верный, назначает роль из токена.
  5. Система привязывает идентификатор устройства к аккаунту.
  6. Система отправляет прогресс устройства на сервер.
- **Альтернативы и ошибки:**
  - 3а. Пароль не проходит требования: сообщение, регистрация не выполнена.
  - 4а. Email уже занят: сообщение.
  - 4б. Токен просрочен, отозван или уже использован: сообщение, аккаунт не создаётся. Регистрация без токена возможна только как User.
  - 4в. Email в форме не совпадает с email токена: сообщение, аккаунт не создаётся.
  - 4г. Нет сети: сообщение и «Повторить», введённые поля сохраняются.
- **Постусловия:** пользователь видит «Профиль» с email и ролью. Аккаунт создан, устройство привязано, прогресс на сервере.
- **Запросы к серверу:** создать аккаунт, привязать устройство, отправить прогресс.

### 1.1.5 Войти

- **Роль:** User, Moderator, Administrator, Owner.
- **Цель:** получить доступ к аккаунту на этом устройстве.
- **Предусловия:** устройство зарегистрировано (1.1.2), аккаунт существует.
- **Исходное окно:** Вход.
- **Итоговое окно:** Home.
- **Основной сценарий:**
  1. Пользователь вводит email и пароль.
  2. Сервер проверяет данные.
  3. Система привязывает идентификатор устройства к аккаунту. У устройства может быть несколько привязок, отвязать их нельзя.
  4. Если на устройстве уже есть прогресс, система выполняет слияние с данными аккаунта (правила ниже). Иначе система загружает данные аккаунта.
  5. Система открывает Home с правами роли аккаунта.
- **Альтернативы и ошибки:**
  - 2а. Неверный email или пароль: сообщение без уточнения, что именно неверно.
  - 2б. Аккаунт заблокирован: сообщение, вход закрыт.
  - 2в. Нет сети: сообщение и «Повторить».
  - *. Аккаунт заблокирован во время сессии: при следующем обращении к серверу система выходит из аккаунта и показывает сообщение.
  - *. Сессия не истекает по времени, она закрывается выходом, блокировкой или удалением аккаунта.
- **Правила слияния.** Данные сравниваются по каждой записи отдельно:
  - урок, тема, запись, текст, набор: побеждает запись с большим прогрессом;
  - слова словаря: объединяются, слово есть на одной стороне добавляется. Для одного слова на обеих сторонах побеждает карточка с более поздней датой последнего повторения;
  - слово с меткой удаления на одной стороне удаляется и на другой, кроме случая, когда последний повтор карточки позже даты удаления;
  - выученное слово: побеждает запись с более поздней датой ответа;
  - streak: большее значение;
  - achievements: объединяются, полученное не теряется. Achievement, неизвестный версии приложения, хранится, но не показывается до обновления;
  - целевой уровень и интересы: побеждает аккаунт.
- **Постусловия:** пользователь видит Home. Устройство привязано к аккаунту, данные объединены.
- **Запросы к серверу:** вход, привязать устройство, получить данные аккаунта, отправить итог слияния.

### 1.1.17 Повторить карточки

- **Роль:** User.
- **Цель:** запомнить слова надолго интервальными повторениями.
- **Предусловия:** в словаре есть активные карточки, срок которых наступил.
- **Исходное окно:** Словарь.
- **Итоговое окно:** Словарь.
- **Основной сценарий:**
  1. Пользователь нажимает «Повторять». Система показывает Flashcards и число карточек к повторению.
  2. Система показывает лицевую сторону: слово, транскрипцию, часть речи.
  3. Пользователь вспоминает перевод и переворачивает карточку.
  4. Система показывает перевод и три кнопки: «Again», «Good», «Easy». На каждой подписан следующий интервал для этой карточки.
  5. Пользователь оценивает ответ.
  6. Система рассчитывает следующий показ и показывает следующую карточку.
- **Правила интервалов.** Интервал растёт по схеме интервальных повторений: «Good» и «Easy» увеличивают интервал карточки, «Again» сбрасывает его до начального. Формула выбирается на техническом этапе.
- **Альтернативы и ошибки:**
  - 1а. Карточек к повторению нет: сообщение «На сегодня всё».
  - 6а. «Again»: интервал сбрасывается, карточка встаёт в конец сегодняшней очереди. Если сессию закрыли до повтора, карточка остаётся в очереди на сегодня со сброшенным интервалом.
  - 6б. Досрочное закрытие: оценённые карточки сохранены, остальные остаются в очереди.
  - *. Неактивные карточки в очередь не попадают.
  - *. Сессия Flashcards не считается занятием для streak и не меняет статус «выучено».
- **Постусловия:** пользователь видит «Словарь» с обновлённым числом карточек к повторению. У каждой оценённой карточки обновлены интервал и дата следующего показа.
- **Запросы к серверу:** нет. При наличии аккаунта данные уходят при синхронизации.

- **Исходное окно:** Скачанные разделы.

  - 3а. Отказ: ничего не меняется.
  - 4а. Нет сети: действие невозможно, сообщение.
  - *. Роль Administrator назначает и снимает только Owner: токеном при регистрации (1.1.25) или действием «Назначить Administrator» у существующего аккаунта.
  - *. Заблокировать Owner нельзя. Заблокировать Administrator может только Owner.
  - *. Разблокировать может Administrator, который заблокировал, и Owner.
  - *. Заблокированный пользователь при следующем обращении к серверу выходит из аккаунта с сообщением.
- **Постусловия:** Administrator видит новую роль или статус в списке. Действие записано в журнал.
- **Запросы к серверу:** найти пользователя, изменить роль, заблокировать, разблокировать, записать в журнал.

### 1.1.25 Выдать токен-приглашение

- **Итоговое окно:** Токены-приглашения.
- **Основной сценарий:**
  1. Owner выбирает «Создать токен».

### 1.1.26 Отозвать токен-приглашение

- **Роль:** Owner.
- **Цель:** сделать неиспользованный токен недействительным.

### 1.1.28 Данные клиента

Таблица 3 — Данные клиента

| Данные | Где хранятся |
|---|---|
| Идентификатор устройства | Устройство, защищённое хранилище ОС |
| Целевой уровень, интересы | Устройство, при наличии аккаунта копия на сервере |
| Прогресс: уроки, темы, записи, тексты, наборы, последний результат | Устройство, при наличии аккаунта копия на сервере |
| Незавершённый тест уровня | Только устройство |
| Место в прерванном занятии, черновики Homework, список пропущенных заданий | Только устройство |
| Словарь: слова, карточки, интервалы, даты показа, статус «выучено», метки удаления | Устройство, при наличии аккаунта копия на сервере |
| Streak, полученные achievements | Устройство, при наличии аккаунта копия на сервере |
| Настройки | Только устройство |
| Скачанные разделы | Устройство |
| Контент не скачанного раздела | Сервер, только онлайн |
| Аккаунт, роль | Сервер, сессия на устройстве |
| Материалы, очередь проверки, пользователи, токены | Сервер, только онлайн |

**Состояния окон.** Окно, которое берёт данные с сервера, имеет четыре состояния: загрузка, пусто, ошибка с «Повторить», нет сети. Окно на локальных данных имеет только состояние «пусто».

**Синхронизация.** Для пользователя с аккаунтом данные уходят на сервер после каждого завершённого занятия и каждой оценки карточки при наличии сети. Накопленное без сети уходит при первой сети. Без сети всё локальное работает, индикатор ошибки синхронизации не показывается. Данные без аккаунта остаются только на устройстве, на сервере лежат идентификатор и счётчик занятий. Контент не скачанного раздела не кэшируется.
